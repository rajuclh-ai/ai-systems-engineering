# LLM Evaluation Framework

An evaluation framework for LLM-powered systems — covering RAG pipelines and AI agents. Runs locally and in CI, fails the build when quality drops below defined thresholds, and tracks metrics over time.

Built to evaluate two existing systems:
- [`arxiv-expert-rag`](../arxiv-expert-rag) — RAG pipeline over research papers
- [`pr_review_agent`](../pr_review_agent) — AI agent that reviews pull requests

## Inputs

### 1. RAG Test Dataset (`datasets/arxiv_rag_testset.json`)

Auto-generated by RAGAS `TestsetGenerator` on first run from the arxiv paper corpus.
Re-used on every subsequent run.

```json
[
  {
    "question": "What is LoRA and how does it reduce memory usage?",
    "ground_truth": "LoRA inserts low-rank adapter matrices into transformer layers..."
  }
]
```

### 2. Agent Test Dataset (`datasets/pr_agent_testset.json`)

7 hand-crafted PRs, each with a real intentional bug and a diff. Covers:
- Off-by-one errors
- Inverted conditions
- Broken cache logic
- Null dereference
- Token expiry flip

```json
[
  {
    "pr_id": "pr-001",
    "diff": "- if user.age > 18:\n+ if user.age >= 18:",
    "known_bugs": ["off-by-one: 18-year-olds excluded from access"]
  }
]
```

### 3. Eval Config (`eval_config.yaml`)

```yaml
model: gpt-4o-mini
temperature: 0

rag:
  dataset: datasets/arxiv_rag_testset.json
  generate_n: 10
  thresholds:
    faithfulness: 0.70
    answer_relevance: 0.70
    context_recall: 0.65
    context_precision: 0.65

agent:
  dataset: datasets/pr_agent_testset.json
  thresholds:
    bug_recall: 0.70
    false_positive_rate: 0.40
    comment_quality: 0.60
```

## Metrics Reference

### RAG Metrics (via RAGAS)

| Metric | What it measures | Threshold |
|---|---|---|
| Faithfulness | Is the answer grounded in the retrieved context? | ≥ 0.70 |
| Answer Relevance | Does the answer address the question? | ≥ 0.70 |
| Context Recall | Did retrieval surface the right chunks? | ≥ 0.65 |
| Context Precision | Are retrieved chunks relevant (not noisy)? | ≥ 0.65 |

### Agent Metrics (LLM-as-judge)

All three agent metrics use GPT-4o-mini as the judge — keyword overlap was discarded because the
agent's output vocabulary never matches the `known_bugs` descriptions exactly.

| Metric | What it measures | Judge prompt | Threshold |
|---|---|---|---|
| Bug Recall | Did any comment address each known bug? | "Does this comment catch this bug, even with different wording?" → bool | ≥ 0.70 |
| False Positive Rate | What fraction of comments raise non-issues? | "Is this comment raising a real, actionable concern?" → bool (false = FP) | ≤ 0.40 |
| Comment Quality | How accurate and actionable is each comment? | "Score 0.0–1.0 on accuracy, actionability, relevance" → float | ≥ 0.60 |

## Setup

```bash
# 1. Clone and install
cd llm-eval-framework
pip install -r requirements.txt

# 2. Configure environment
cp .env.example .env
# Add your OPENAI_API_KEY to .env

# 3. Run all evals (generates RAG testset on first run)
python cli.py run

# 4. Run a specific target
python cli.py run --target rag
python cli.py run --target agent

# 5. View history
python cli.py history --last 10
```

## CI Integration

The GitHub Actions workflow (`.github/workflows/eval.yml`) runs on every push to `main`:

1. Checks out the eval framework and both target projects
2. Installs all dependencies
3. Runs `python cli.py run`
4. Exits with code `1` if any metric is below threshold — **failing the build**
5. Uploads the full `outputs/` folder as a build artifact
